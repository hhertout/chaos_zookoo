# chaos_zookoo documentation site

Docusaurus-powered documentation for `chaos_zookoo`. The site sources live
under `docs/` — one page per concept/module/middleware.

## Local development

```bash
cd documentation
npm install       # first time only
npm start         # dev server with hot reload on http://localhost:3000
```

## Production build

```bash
npm run build     # static site in ./build
npm run serve     # serve ./build locally to validate
```

`npm run build` fails on broken internal links — useful as a CI gate on
documentation PRs.

## Structure

```
docs/
├── intro.md                    # landing page
├── getting-started/            # install + configure + run
├── modules/                    # one page per kind (Killing, GorillaKill, Rollout)
├── middlewares/                # loadkit, testkit
├── concepts/                   # matchers, scheduling, metrics
├── deployment/                 # Helm + RBAC
└── development/                # architecture + contribution guide

sidebars.ts                     # explicit sidebar tree
docusaurus.config.ts            # site config (title, navbar, footer, prism)
src/pages/index.tsx             # homepage hero
src/components/HomepageFeatures # "why chaos_zookoo" feature strip
```

## Conventions

- Each page starts with YAML frontmatter (`title`, `sidebar_position`).
- Use relative markdown links between docs (`./modules/killing.md`,
  `../concepts/matchers.md`) — they're checked at build time.
- Code fences declare their language (`yaml`, `go`, `bash`, `promql`) to
  get syntax highlighting.
- The sidebar is defined explicitly in `sidebars.ts`, not autogenerated.
  When adding a page, add it to the tree.
